# Reglas iniciales

- El motor de base de datos del proyecto es SQL Server.
- La aplicación se desarrollará con ASP.NET Core MVC.
- El acceso a datos usará ADO.NET con SQL parametrizado.
- La fuente de verdad para esquema y datos es el script del grupo `database/01_Crear_Base_Datos.sql` y, para datos de prueba, `database/02_Datos_Prueba.sql`. Leerlos antes de cualquier tarea dependiente de la base de datos.
- Para la implementación autorizada en esta etapa, usar la referencia visual adjunta por el usuario: sidebar azul marino, turquesa y coral, fondos claros y tarjetas redondeadas. `docs/prototipos/Propuesta_Coral_Turquesa.png` no estaba en el proyecto al iniciar esta etapa.
- Se autoriza desarrollar layout, acceso con autenticación por cookies y contraseña con hash, dashboard y CRUD simples de Categorías, Sucursales, Proveedores y Clientes. `Tbl_Usuarios` requiere la migración independiente autorizada y respaldo SQL verificado antes de aplicarse.
- Los formularios Agregar/Editar usan modales; paginar, filtrar y mostrar KPI consultados de SQL Server.
- Usar solamente columnas definidas en los scripts del grupo. Se autoriza el CRUD de Tbl_Empleados con su FK CodigoSucursal hacia Tbl_Sucursales y el módulo Tbl_Ventas/Tbl_VentasDetalle con encabezado-detalle y confirmación transaccional: borradores editables/eliminables sin afectar inventario; confirmar descuenta una sola vez sin existencias negativas; confirmadas y anuladas solo consulta, sin anulación. Se autoriza registrar y consultar Tbl_Pagos y saldos por venta: solo pagar confirmadas con saldo positivo, sin sobrepagos, transaccionalmente; total agregado redondeado una vez a dos decimales, pagos Aplicados por su Monto completo sin restar Comision; conservar saldos negativos existentes; sin editar, eliminar ni anular pagos. Se autoriza integrar únicamente Tbl_Compras/Tbl_ComprasDetalle desde el proyecto de la integrante, adaptado al esquema principal: borradores editables y eliminables sin afectar inventario; recepción desde Borrador con detalles e inventario existente, mediante SqlTransaction, bloqueos de concurrencia y COMMIT/ROLLBACK; sumar existencias y recalcular costo promedio ponderado incluyendo descuento monetario, redondeando a dos decimales; no crear inventarios; Recibidas y Anuladas solo consulta. Se autoriza adaptar el Login de la integrante y preparar una migración independiente de Tbl_Usuarios basada en su esquema. Se autoriza Tbl_AjustesInventario/Tbl_AjustesInventarioDetalle: CRUD de Borradores con múltiples líneas firmadas; aplicar una sola vez mediante SqlTransaction, sin existencias negativas, fijando CostoUnitario desde CostoPromedio vigente; Aplicados y Anulados solo consulta. La migración 04 fue aplicada y verificada por el usuario. Se autoriza el CRUD de Tbl_Productos y la administración de Tbl_ProductoProveedor, con categoría y proveedores reales, código de barras y parejas sin duplicados, importes positivos y estados del esquema; eliminar solo registros de práctica sin dependencias y conservar mediante inactivación los catálogos con movimientos. Se autoriza el módulo de consulta de Tbl_Inventario por producto y sucursal con búsqueda, filtros, paginación y KPI de solo lectura; las existencias se actualizan únicamente mediante Compras, Ventas y Ajustes. No implementar otros CRUD con claves foráneas, encabezado-detalle ni Power BI en esta etapa.
- Está prohibido modificar el esquema de la base de datos sin permiso explícito.
- No ejecutar scripts SQL ni sentencias destructivas sin confirmación explícita del usuario.
- Se permite implementar el acceso autenticado, panel y CRUD indicados por la autorización vigente; no implementar funcionalidades fuera de ese alcance.
- El acceso a SQL Server se limita a lecturas y validaciones necesarias. No ejecutar scripts SQL ni INSERT, UPDATE o DELETE de prueba. Las acciones CRUD solo se ejecutan si un usuario las solicita explícitamente desde la aplicación.
- No usar GitHub, Git remoto ni commits para esta etapa.
- No inventar tablas, columnas, relaciones, datos dependientes del esquema ni credenciales.
- No sobrescribir archivos existentes sin autorización explícita.
